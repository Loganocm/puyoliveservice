Resolves `ENG-01` to `ENG-06`, `RUL-04`, `RUL-05`, and makes every `RUL-*`
decision implementable. Roadmap items P1.1 and P1.2.

Engine v2 is an **evolution of the current engine, not a rewrite**. Every step
below keeps the characterization goldens green, or changes them deliberately
behind an ADR and a version bump.

## State as a value

```ts
interface EngineState {
  frame: number;
  grid: Uint8Array;            // 6 × 14, column-major, one byte per cell
  phase: Phase;                // SPAWN | ACTIVE | FALLING | CHECK | POP | GARBAGE | OVER
  phaseTimer: number;
  active: { x: number; y: number; rot: 0 | 1 | 2 | 3; main: Color; sub: Color } | null;
  queue: { cursor: number };   // index into the match's precomputed sequence
  lock: { timer: number; resetsLeft: number };
  input: { softDrop: boolean; softDropLocked: boolean; glide: boolean };
  garbage: { tray: number; scheduled: { frame: number; points: number }[]; remainder: number };
  rng: { garbage: number };    // the piece stream is precomputed, so only garbage needs state
  stats: Stats;
}
```

- `snapshot()` returns a copy (a few hundred bytes); `restore(s)` replaces the
  state. Rollback saves one snapshot per frame in a ring buffer.
- `hash()` covers the entire state, using FNV-1a or xxHash32 over a canonical
  byte encoding. The server hashes every frame; clients every 60 frames.
- The engine class becomes a thin shell of functions over the state. No
  consumer writes engine fields; they send inputs.

## Rulesets

```ts
interface Ruleset {
  id: 'live-v1' | 'live-v2' | 'tsu' | string;
  colors: 4 | 5;
  sequence: 'deck-pairs-100' | 'tsu-256';
  chainPower: number[]; colorBonus: number[]; groupBonus: number[]; multiplierCap: number;
  targetPoint: number; margin: { startSeconds: number; stepSeconds: number; factor: number; maxSteps: number } | null;
  allClearBonusPoints: number;
  maxGarbagePerDrop: number;
  garbageHoldUntilChainEnds: boolean;
  timing: { gravity: number; lockDelay: number; pop: number | 'scaled-v1'; fallStep: number | 'scaled-v1' };
  lockResets: number;           // Infinity reproduces v1
  glideBuffer: 'unbounded' | 'budgeted' | 'off';
  quickTurn: boolean; diagonalKicks: boolean;
  deathCell: { col: number; row: number; when: 'spawn-blocked' | 'after-resolve' };
  hiddenRowsPop: boolean; row14Vanishes: boolean; freeAboveField: boolean;
}
```

Presets:

| Preset | Purpose |
|---|---|
| `live-v1` | Exactly today's behaviour, bugs included. Replays recorded before engine v2 play back under it |
| `live-v2` | Today's feel with the bugs fixed: separate RNG streams, lock-reset budget of 15, bounded glide |
| `tsu` | The competitive standard ([rules fidelity](/review/rules-fidelity/)) |

The ruleset id and its hash are recorded in every replay and announced at
match start, so both clients and the server provably run the same rules.

## Independent random streams

The match seed (from a CSPRNG, NET-08) is expanded with SplitMix64 into
independent streams:

- **pieces**: the whole match's sequence is generated at match start, shared by
  both players by construction;
- **garbage, per player**: column shuffles for that player's drops only.

Receiving garbage can then never change a player's pieces (RUL-04).

## Typed events

Twenty optional callback fields become one typed event stream:

```ts
type EngineEvent =
  | { t: 'spawn'; pair: Pair } | { t: 'move'; dx: -1 | 1 } | { t: 'rotate'; kick: Kick }
  | { t: 'lock'; cells: Cell[] } | { t: 'pop'; chain: number; groups: Group[] }
  | { t: 'garbage-sent'; points: number } | { t: 'garbage-drop'; columns: number[] }
  | { t: 'all-clear' } | { t: 'top-out'; reason: 'spawn' | 'lock' } | …;

const events = engine.step(inputsForThisFrame);
```

The renderer, audio, recorder, replay and lab subscribe to the same stream.
That removes the hook-wrapping the lab needs today, and makes "what happened
this frame" a value that can be tested and diffed.

## Garbage scheduling

`scheduleGarbage(points, arriveFrame)` replaces `addGarbage(rocks)`. Garbage
generated by a chain link at frame *f* arrives in the opponent's tray at frame
*f + D* (*D* from the ruleset, or held until the chain ends under `tsu`). This
makes garbage timing a function of the match, not of the network (NET-05), and
it is what makes [rollback](/architecture/netcode/) cheap.

## Migration plan

Each step is its own pull request with an ADR where behaviour changes:

1. **State extraction** without behaviour change: move fields into
   `EngineState`, add `snapshot`/`restore`/full `hash`. Goldens unchanged.
2. **Typed events** alongside the old callbacks; migrate consumers; remove the
   callbacks.
3. **Ruleset object** with `live-v1` reproducing today exactly, verified by the
   goldens and the [animation catalogue](/reference/animation-catalogue/).
4. **`live-v2`** (fixes RUL-04, RUL-05): new goldens, ADR, `ENGINE_VERSION`
   2.0.0. Replay playback selects `live-v1` for older replays.
5. **`tsu` preset**: rules fidelity tests against the reference tables.
6. **Garbage scheduling**, together with [netcode](/architecture/netcode/) phase 1.
